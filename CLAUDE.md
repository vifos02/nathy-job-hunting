## Scoring Rubric

Score each posting 1–10 on five dimensions, then calculate a weighted final score.

### 1. Role Fit (weight: 30%)
Does the title and scope match my 16-year trajectory? Would I be underqualified or overqualified?
- 10 = perfect match (senior digital/SEO/content/growth role in a relevant industry)
- 7 = good match (adjacent role I can credibly do)
- 5 = partial (half the job fits, half doesn't)
- 2 = wrong level or wrong function entirely

### 2. Remote & Location (weight: 25%)
Is this role workable from Spain now, or from Brazil from November 2026?

**Hard blockers (score 1):**
- Requires US work authorization, US citizenship, or W-2 employment
- On-site only, in a city I won't be in

**Scoring:**
- 10 = fully remote, no location restriction, no work-auth requirement
- 9 = remote; explicitly open to international/global applicants
- 8 = remote within EU only (qualifies via Italian citizenship in progress), or Brazil-based
- 7 = remote with US East Coast hours required (workable from Brazil UTC-3; 2h gap)
- 6 = remote with US Central/Mountain hours (workable from Brazil with some stretch)
- 5 = remote with US Pacific hours or timezone unclear (investigate before applying)
- 4 = hybrid in a city far from current location but possibly workable with travel
- 2 = strong indication of US work authorization required (flag clearly)
- 1 = on-site only in inaccessible city, or explicit US work-auth requirement confirmed

### 3. Compensation (weight: 20%)
Is the pay competitive for a senior professional with 16 years' experience?
- Target: €50k–€70k/year (or equivalent), or USD/EUR contract at $25+/hr
- 10 = clearly meets or exceeds target
- 7 = likely meets target based on company size (if salary undisclosed)
- 5 = borderline or unclear
- 2 = clearly below (startup with no funding, or BRL-only at low rates)

### 4. Company Quality (weight: 15%)
Is this a real company with a real product, healthy culture, and an international English-speaking team?
- 10 = established brand, international team, positive reviews, financially stable
- 7 = solid company, less well-known but credible
- 5 = early-stage startup or limited info available
- 2 = red flags (toxic reviews, no funding visibility, vague product)

### 5. Skill Match (weight: 10%)
How closely do their stated requirements map to my documented skills?
- 10 = strong overlap (SEO, content, social, team leadership, international teams)
- 7 = mostly overlaps, a few gaps in tools I can learn quickly
- 5 = moderate overlap
- 2 = significant technical mismatch (heavy SQL, SEM-only, engineering-adjacent)

---

## Weighted Score Formula

```
Final = (Role Fit × 0.30) + (Remote × 0.25) + (Comp × 0.20) + (Company × 0.15) + (Skills × 0.10)
```

## Writing Voice Rules

Apply these to every cover letter, application answer, and professional text generated by this system. These rules run automatically during /tailor. For a full cleanup pass on finished text, use /humanize.

**Hard constraints — never do these:**
- No em dashes (—). Replace with a comma, period, or colon.
- No rule of three. "X, Y, and Z" forced into one sentence reads like AI. Use one or two.
- No labeled bullet lists with bolded headers ("**Strength:** I did X. **Impact:** Y."). Write prose.
- No generic closing sentences ("I look forward to contributing to your team's success."). End on the last real fact.
- No sycophantic openers ("I am thrilled/excited/passionate to apply..."). Start with something specific.
- No "not only X, but also Y" constructions.
- No signposting ("Let me walk you through...", "Here's what you need to know").

**Banned words in any application text:**
- crucial, pivotal, vibrant, landscape (abstract), tapestry, testament, underscore, delve, garner, showcase, highlight (verb), interplay, intricate, fostering, enhancing, boasts
- "I am passionate about"
- "I would be a great fit"
- "in order to" (use "to")
- "due to the fact that" (use "because")
- "at this point in time" (use "now")

**Style rules:**
- Vary sentence length. Short and long sentences should alternate. An even mid-length cadence reads as AI.
- Lead with the specific fact, not the claim. "I ran a 22,000-lead launch in 7 days" not "I have a strong track record of results."
- Use is/are/has instead of serves as / stands as / represents / boasts.
- Cut -ing tailing phrases that pile fake depth onto sentences: "fostering collaboration...", "highlighting my ability to...", "contributing to the growth of..."
- Drop excessive hyphenation in predicate position: "the work is data driven" not "the work is data-driven."

**No-fabrication rule (absolute):**
All specifics in any rewrite must come from resume/master-resume.md, resume/knowledge-base.md, or what the user explicitly states. Do not invent metrics, outcomes, tools, or claims to make a sentence sound more grounded.

## Scanning Workflow

### Cadence

Run the full scan cycle **twice a day** — once in the morning, once mid-afternoon.

### Script Split by Environment

| Script | Where it runs | What it covers |
|--------|--------------|----------------|
| `scan_jobs.py` | Local Mac, Terminal | ATS APIs: Greenhouse, Lever, Ashby, Workday, Gupy, Workable — plus aggregators: Remote OK, Remotive, Working Nomads, We Work Remotely |
| `browser_search.py` | Local Mac, Terminal | Indeed (remote filter, 14 days), LinkedIn (remote, 7 days), Remote.co |

Both scripts run locally. The Claude Web remote session cannot make outbound HTTP requests due to network egress policy — it is used only for Claude AI interactions (evaluate, tailor, digest, humanize, prep).

### Running Both Scanners (Local Mac Terminal)

```bash
cd ~/path/to/nathy-job-hunting
git pull                              # sync dedup list before every run

pip install requests playwright       # one-time setup

python scan_jobs.py                   # API scanner — ATS + aggregators
python browser_search.py              # browser scanner — Indeed, LinkedIn, Remote.co

git add evaluated-jobs.csv browser-finds.json
git commit -m "scan $(date +%Y-%m-%d-%H%M)"
git push
```

Always `git pull` first. Both scripts share `evaluated-jobs.csv` as the dedup record — running either one without a pull risks logging duplicates already found by the other.

### After Each Scan

1. New matches print to stdout
2. Open a Claude Web session (personal account) and paste interesting postings into `/evaluate` to score them
3. If score ≥ 7.0, run `/tailor` then apply
4. Log the application in `applications.csv`
5. Run `/digest` for a current pipeline view

## Outreach Tracker

`outreach-tracker.csv` logs every networking touch. Columns:

| Column | Notes |
|--------|-------|
| date | Date message was sent (YYYY-MM-DD) |
| person | Full name of the contact |
| company | Their company |
| platform | LinkedIn, Email, Twitter/X, WhatsApp, other |
| status | Sent, Replied, Meeting Booked, No Response, Declined |
| follow_up_date | Date to follow up if no reply (YYYY-MM-DD) |
| message | Exact text sent — used to track what gets responses |
| notes | Who they are, their role, any context |

The `message` column is intentionally verbatim. Over time the pattern of what gets replies vs. silence will be visible in the data.
